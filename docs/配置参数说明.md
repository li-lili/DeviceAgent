# Android 配置参数

入口文件 device-agent.conf 可用 environment=cloud 选择同目录 device-agent.cloud.conf。
identity-source：身份来源，file（缺省）或 vendor-storage。vendor-storage 经 libfactory_service 直接读 RK3588 Vendor Storage 的 SN 与私钥，仅用于 Ubuntu 板端；Android 侧固定 file。vendor-storage 下 SN 缓存到 state-dir/sn.cache（明文、0600，与 Token 同级敏感度）：token 有效时启动不再读裸 eMMC 设备，仅在重新 enroll 时重读校验；库加载失败时告警并回退 file 来源（device-file / private-key）。
factory-lib：vendor-storage 模式下 libfactory_service.so 路径覆盖，缺省 libfactory_service.so.1。
device-file：只含一行 SN 的文本文件路径，读取后作为业务 SN；与 device 同时写时必须一致。SN 与私钥都不在配置里写明文，程序不会自动读取 Android 属性。
private-key：设备私钥文件路径，Agent 只读，不生成密钥；支持 PKCS#8 / PKCS#1 PEM 与 OpenSSH 格式（无口令）。产线默认位置为 /userdata/container/android_data/data_0/local/factory/keys/device_rsa，SN 文件同目录 sn.txt。
身份等待：SN 或注册所需私钥尚未写入、为空或格式不完整时，进程不退出，每 10 秒重读；写入后自动继续。日志使用 IDENTITY waiting/ready，不打印私钥内容。等待期间不发送注册请求；已有 Token 时仍按缓存连接。
enroll-url：HTTPS 签名换 Token 地址。
配置 enroll-url 或 mqtt-url 时，启动先等待注册与 MQTT 目标的 DNS 解析和 TCP 连接均成功，再注册或连接 MQTT。MQTT 目标优先取 mqtt-url，否则取 host/port；地址不写死。每次连接检测超时 5 秒，每轮失败后等 5 秒，等待期间不发送 HTTP 注册或 MQTT 报文，可用 SIGTERM/SIGINT 停止。TCP 可达不代表业务认证成功，也不能消除服务端 429；不额外重试注册接口。即使已有 Token，也先等待配置的两个目标就绪。
https-ca：受信公共 CA bundle；不得使用 localhost CA 或关闭验证。
host、port：云端 MQTT；username 默认使用 SN，Token 作为密码。
ca：仅用于 MQTT TLS，与 HTTPS 的 https-ca 分开配置。
state-dir：状态和 Token 根目录；Token 默认位于 tokens/SN.token。
work-dir：临时任务目录。log-file：运行日志文件。
sources-config：业务日志来源 JSON；首次联调应仅允许独立空测试目录。
token、token-file 优先于签名 enroll；要验证设备端签名，应使用新的隔离状态目录，不删除已有 Token。
相对路径以配置文件所在目录为基准。SN、公钥、私钥和 Token 不随包分发。
