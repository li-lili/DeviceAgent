# 日志系统顶层设计

### 文件命名与采集

所有受管业务日志、C++ SDK 日志和第三方日志的文件名统一规定为 **`yyyy_MM_dd_HH_mm_ss.log`**，使用北京时间（UTC+8），时间表示该文件开始写入的时间。年月日、时分秒均补零，各部分之间以下划线分隔，不增加来源前缀、序号或其他后缀。例如：

```text
2026_10_21_09_05_03.log
2026_10_21_09_18_42.log
2026_10_22_00_00_00.log
```

来源通过目录区分。各写入端按规定生成文件名；Agent 的文件名匹配配置仍然保留，不在程序中取消或硬编码这些配置项。

同一目录仅允许一个轮转写入者。同一秒内重复启动、轮转或系统时间回拨时，必须检查目标文件是否已存在，禁止覆盖旧文件；仅可由同一写入者安全续写尚未达到大小阈值的文件，否则等待到可用的新时间再创建文件。等待期间使用有界缓冲或降级处理，不得无限积压。多进程或多个第三方组件使用各自子目录，避免同名冲突。

Agent 目前按文件名中的日期选择整份文件，不按文件名时分秒截取内容。`filename_date_formats` 填写 `%Y_%m_%d`（对应 `2026_10_21_09_05_03.log`），不需要整串 `yyyy_MM_dd_HH_mm_ss.log`；当前解析器不支持 `%H`、`%M`、`%S`，时分秒不参与筛选。

按日期采集时选择文件名日期匹配的所有文件，并受采集包大小限制；最新文件模式每个来源只选一份。是否跨天创建文件由业务端决定；未跨天轮转的文件可能包含多天日志，当前按文件名日期筛选不等于按内容日期完整采集。业务历史日志初期保持普通文件形式，不额外压缩，以匹配当前文件名筛选和原文件打包方式。


### 目录约定

Android 日志根目录：**待 Android 负责人指定**，本文暂以 `<ANDROID_LOG_ROOT>` 占位。负责人确定实际绝对路径，并确认指定业务 App、SDK 宿主进程、第三方组件可写入，Agent 可读取和遍历。Linux 统一使用 `/var/log/deviceagent/`，与程序、配置及 Token 分开管理。

| 平台 | 日志类别 | 规定目录 | 建议 source_id |
| --- | --- | --- | --- |
| Android | 业务日志 | `<ANDROID_LOG_ROOT>/business/` | `business` |
| Android | C++ SDK 日志 | `<ANDROID_LOG_ROOT>/cpp-sdk/` | `cpp_sdk` |
| Android | 第三方日志 | `<ANDROID_LOG_ROOT>/third-party/<组件名>/` | `third_party_<组件名>` |
| Linux | 业务日志 | `/var/log/deviceagent/business/` | `business` |
| Linux | 第三方日志 | `/var/log/deviceagent/third-party/<组件名>/` | `third_party_<组件名>` |

实际日志目录、组件划分和来源 ID（`source_id`）由项目维护者与端侧负责人共同约定，表中的 `business`、`cpp_sdk`、`third_party_<组件名>` 仅为建议值。`<组件名>` 替换为实际名称；同类多个业务或 SDK 写入者应按组件建立独立子目录。每个需要独立采集的来源配置独立的 `source_id`，在同一设备内唯一；名称为 1～64 位英文字母、数字、下划线、点或连字符，不能为 `.` 或 `..`。表中业务、SDK 和第三方来源按“初始策略”约定单文件大小及文件数量。

Android 目录的选择、创建及访问权限由 Android 负责人落实，包含文件权限、适用的存储访问机制及 SELinux 策略。现有 SELinux 路径模板需按最终目录核对调整，不能假定指定一个路径后普通 App 即可访问。Linux 由部署脚本创建目录，分配对应服务用户、用户组及读取权限。禁止为方便共享设置全局可写权限。

第三方组件接入时需配置其输出目录、文件名和轮转规则；若组件不支持约定格式，需要增加日志输出适配，不能仅修改 Agent 配置就视为完成接入。


### 初始策略

统一策略只约束单文件大小和保留文件数量，不规定按天轮转或按天保留；业务端自行决定是否跨天切换、保留多久及其他时间策略。

| 项目 | 建议值与规则 |
| --- | --- |
| 单个业务日志文件 | 默认 50 MiB；高产量来源可调整为 100 MiB。达到阈值后由写入端轮转，允许因最后一条完整记录略微超限。 |
| 业务日志文件数量 | 业务、C++ SDK 和第三方来源合计默认最多保留 100 个文件，含当前写入文件；由项目维护者与端侧约定各来源配额，配额合计不超过总数量上限。该数量为初始建议，可按来源数量和设备空间调整。 |
| Agent 自身日志 | 单文件 10 MiB，最多保留 5 个文件，含当前写入文件。 |
| 临时采集包 | 创建和写入时检查可用空间，任务结束后清理；不计入历史日志文件数量。 |

以上单位采用二进制：1 MiB = 1024² 字节。不同来源使用独立目录和数量配额，不按每个来源重复分配全部 100 个文件。


### 采集包命名

日志采集包统一命名为 **`log_<sn>_<打包时间>.tar.gz`**（尖括号仅作占位，实际文件名不含 `<>`），其中 `<sn>` 只取设备 SN 中 `BJ` 起（含 `BJ`）的后缀。例如：

```text
log_BJ_20261028_1002_20261022_143025.tar.gz
```

- `<sn>` 取设备 SN 中第一次出现 `BJ` 之后的整段（含 `BJ`），如 `NTX_W1XXXXXXXX_V1.1.0_BJ_20261028_1002` 取为 `BJ_20261028_1002`；SN 中不含 `BJ` 时使用完整 SN。协议中的 `device_id` 字段名保持不变，其值填写完整设备 SN。
- `<打包时间>` 使用北京时间（UTC+8），格式为 `yyyyMMdd_HHmmss`，表示本次任务开始打包的时间。同一任务因包大小限制而重新打包时，保持该时间和文件名不变。

端侧临时包文件名与上传申请中的 `filename` 均按上述规则生成；`<sn>` 已在端侧校验为合法标识，不含路径分隔符。云端存储对象键和 `file_id` 继续按上传凭证管理，不要求与下载文件名一致，模拟程序仍以 `<file_id>.tar.gz` 落盘。

### 轮转与清理规则

1. 写入端在文件达到大小阈值时关闭当前文件并创建下一份文件，保留完整日志记录。跨天轮转、按天保留等时间策略由业务端自行处理，不作为统一要求。
2. 各来源超过约定文件数量上限时，由对应文件管理模块按最旧优先清理已关闭的历史文件，不按文件年龄执行统一的 7 天或其他天数清理。
3. 当前写入文件和正在采集的文件应受保护，不能被清理或截断。采集与清理之间需要文件占用标记或等效协调机制；具体实现另行确定。
4. 仅清理已配置日志目录中的受管历史文件，不能删除其他业务数据。轮转和清理应串行协调，避免文件命名冲突或重复删除。
5. 达到数量上限且没有可清理文件时，暂停或降低普通日志写入并报告状态，不能无限创建文件。空间不足时报告失败；临时采集任务终止并清理临时文件，不得无限重试或继续写满磁盘。
6. 写入端在创建文件及轮转时检查大小和数量，保护解除后补做必要清理。

### 职责划分

| 模块 | 职责 |
| --- | --- |
| 业务日志写入端及其文件管理模块 | 落实约定的单文件大小、文件数量、轮转、清理和命名；自行处理时间策略；提供正在写入文件的识别方式。 |
| DeviceAgent | 根据配置选择文件、打包上传、清理本任务临时文件，并参与采集文件保护；不统一接管业务端时间策略。 |
| 云端 | 下发采集命令，展示采集结果。 |

每个来源的清理动作由端侧约定的一个模块负责，避免业务端与 Agent 各自独立删除同一批文件。

### 配置保持可用

`log-sources.json` 及 `sources-config` 继续生效，实际采集路径、来源 ID、递归开关、匹配规则及日期格式均以配置文件为准。以上目录和命名为项目部署约定，**不删除可配置能力，也不将采集路径在代码中写死**。项目维护者根据与端侧约定的结果统一维护、分发 `log-sources.json`，修改后重启 Agent；端侧负责按约定输出日志并落实 Agent 读取权限。文件采集模式下，端侧无需在业务代码中注册 `source_id`；云端按来源采集时使用 JSON 中约定的 `source_id`。

Android 示例（`<ANDROID_LOG_ROOT>` 仅为文档占位符，不是环境变量，程序不会自动展开；由维护者替换为 Android 负责人确定的实际绝对路径后使用）：

```json
{
  "log_sources": [
    {
      "source_id": "business",
      "path": "<ANDROID_LOG_ROOT>/business",
      "recursive": true,
      "file_patterns": ["*.log"],
      "filename_date_formats": ["%Y_%m_%d"]
    },
    {
      "source_id": "cpp_sdk",
      "path": "<ANDROID_LOG_ROOT>/cpp-sdk",
      "recursive": true,
      "file_patterns": ["*.log"],
      "filename_date_formats": ["%Y_%m_%d"]
    },
    {
      "source_id": "third_party_camera",
      "path": "<ANDROID_LOG_ROOT>/third-party/camera",
      "recursive": true,
      "file_patterns": ["*.log"],
      "filename_date_formats": ["%Y_%m_%d"]
    }
  ]
}
```

Linux 示例：

```json
{
  "log_sources": [
    {
      "source_id": "business",
      "path": "/var/log/deviceagent/business",
      "recursive": true,
      "file_patterns": ["*.log"],
      "filename_date_formats": ["%Y_%m_%d"]
    },
    {
      "source_id": "third_party_camera",
      "path": "/var/log/deviceagent/third-party/camera",
      "recursive": true,
      "file_patterns": ["*.log"],
      "filename_date_formats": ["%Y_%m_%d"]
    }
  ]
}
```

示例中的 `camera` 是组件占位示例，部署时由维护者替换或增删来源。`*.log` 仅筛选扩展名，不验证完整命名规范；固定文件名格式由写入端和接入验收保证。

Agent 自身运行日志、设备 Token、状态文件及临时采集包不混入上述受管业务日志目录；其存放路径继续由各自配置项管理。Agent 当前自身日志仍由 `log-file` 指定，此处统一命名规则针对被采集的各类日志文件。

### 当前实现与待办



当前 `log_sources` 配置用于声明日志路径、递归扫描、文件名匹配和日期格式，DeviceAgent 选择整份文件打包上传，并清理任务临时文件。

本文提出的单文件大小与文件数量控制、端侧轮转清理及采集保护，以及 Agent 自身日志轮转，需分别落实实现和验证。时间策略由业务端自行实现。上述大小与数量参数尚不能直接添加到现有 `log_sources` 中生效。

设计参考：[Apache Log4j 文件轮转机制](https://logging.apache.org/log4j/2.x/manual/appenders/rolling-file.html)、[systemd 日志容量与剩余空间管理](https://www.freedesktop.org/software/systemd/man/247/journald.conf.html)。本文具体容量数值为本项目建议值。
