# DeviceAgent 云端使用说明

本文介绍设备接入云端后的配置、运行、日志采集和下载流程，适用于当前 Ubuntu 22.04 / WSL Ubuntu-22.04 版本。Agent 是 C++17 前台程序，通过 MQTT 5 + JSON 接收命令，选择业务日志文件、打包并上传。

## 1. 配置与目录

| 文件或目录 | 用途 |
| --- | --- |
| `device-agent.conf` | 选择云端配置，设置为 `environment=cloud` |
| `device-agent.cloud.conf` | 真实云端设备码、注册码，仅两个参数 |
| `log-sources.json` | 日志来源目录和文件名规则 |
| `build/device-agent` | 编译生成的 Linux 可执行程序 |
| `business-logs/app/` | 当前 business 来源的原始日志 |
| `business-logs/sdk/` | 当前 camera_sdk 来源的原始日志 |

Agent 不接收命令行参数。所有设置从文件读取，修改配置后重启生效。

## 2. 进入 WSL 与编译

Windows PowerShell 中执行：

```powershell
wsl -d Ubuntu-22.04
```

随后在 WSL 中进入项目：

```bash
cd /home/liziang/DeviceAgent
```

**下文未特别标注的命令均在 WSL / Ubuntu Bash 的项目目录执行。** 不要直接在 PowerShell 中执行 Linux 可执行程序 `./build/device-agent`。

Windows 文件管理器中的项目路径是：

```text
\\wsl.localhost\Ubuntu-22.04\home\liziang\DeviceAgent
```

首次安装依赖并编译：

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake pkg-config protobuf-compiler libprotobuf-dev \
  libmosquitto-dev libarchive-dev libcurl4-openssl-dev libssl-dev
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j2
```

成功后生成 `build/device-agent`。修改 C++ 代码需重新编译；修改配置或新增业务日志无需重新编译。Agent 运行不依赖 Python。

## 3. 云端接入

### 3.1 填写配置

`device-agent.conf` 选择：

```ini
environment=cloud
```

`device-agent.cloud.conf` 仅填写设备码、注册码：

```ini
# 设备码，与云端设备一致。
device=rbt-001
# 替换成有效注册码，这里不填写设备 Token。
enrollment-key=在这里填写注册码
```

注册码是云端提供的凭证，不是自己任意设置的字符串。不要在截图或共享文档中暴露注册码、Token。

其他参数已内置，无需填写。注意：当前代码内置的是带 `test` 的测试域名；接入生产环境前，需将下表地址替换为云端管理员提供的生产地址并重新编译，不能直接将其视为生产环境。

| 项目 | 当前值 |
| --- | --- |
| MQTT | `emqx.test.humanuniverse.cn:1883` |
| 注册接口 | `https://logserver.test.humanuniverse.cn/v1/enroll` |
| 控制台 | `https://logserver.test.humanuniverse.cn` |
| 注册机型 | `devicesim` |
| MQTT 用户名 | 自动使用设备码 |
| 日志根目录 | 项目下的 `business-logs/` |
| 来源文件 | 项目下的 `log-sources.json` |

更换云端部署地址时，修改 `src/main.cpp` 的 `environment_defaults()` 云端默认值并重新编译。

### 3.2 注册码与 Token

Agent 启动先读取本地缓存：

```text
run/cloud-agent/tokens/<设备码>.token
```

例如设备 `rbt-001` 对应 `run/cloud-agent/tokens/rbt-001.token`。没有缓存时，Agent 使用设备码、注册码调用注册接口，由云端签发 Token，保存后连接 MQTT；后续重启复用缓存。

注册码不能在本地计算成 Token。Token 文件只允许当前 Linux 用户读写，请妥善保存，**清理运行目录时不要删除整个 `run/`**。已注册设备再次注册可能返回 `already_enrolled`，应恢复原 Token 或联系云端管理员处理。更换注册码也不会自动替换已有缓存。

### 3.3 前台启动与连通判断

在 WSL 项目目录启动：

```bash
./build/device-agent
```

也可直接在 PowerShell 使用这一条完整命令：

```powershell
wsl -d Ubuntu-22.04 bash -lc 'cd /home/liziang/DeviceAgent && ./build/device-agent'
```

程序持续占用终端，按 **Ctrl+C** 停止。设备端启动 Agent 后，将直接连接已部署的云端 MQTT 服务。

看到以下输出表示 MQTT 连接和应用层握手已完成：

```text
READY hello handshake complete
```

`AUTH loaded cached device token` 只表示读取了本地 Token，不能单独证明已连接云端。

### 3.4 云端下发采集命令

通过云端控制台或管理 API，对同一个设备码创建日志采集命令（`collect_logs`）：

1. 选择设备，例如 `rbt-001`。
2. 来源填写 `business`、`camera_sdk`，或留空选择全部来源。
3. 日期选择与设备端文件名日期一致；采集当天日志时，应选择北京时间当天。
4. 创建新命令，观察 Agent 终端及云端任务状态。

典型输出：

```text
COMMAND <命令ID> CMD_ACCEPTED
COMMAND <命令ID> CMD_RUNNING
COMMAND <命令ID> CMD_SUCCEEDED
```

失败时输出 `CMD_FAILED` 和错误码。`CMD_SUCCEEDED` 表示 Agent 已完成上传并回报结果，云端还需确认对象及记录状态，以云端最终结果为准。

云端握手用于连接确认和补投已有待执行命令。需要采集日志时，通过控制台或管理 API 创建命令。

### 3.5 日志包在哪

日志包上传到云端对象存储，从云端的命令结果、文件列表或下载入口获取。

`run/cloud-work/` 是设备端临时打包目录，任务后清理。是否成功上传，应检查本次命令结果和云端文件记录，不能仅凭握手成功判断。

## 4. 日志来源与按天采集

编辑 `log-sources.json`，示例：

```json
{
  "log_sources": [
    {
      "source_id": "business",
      "path": "business-logs/app",
      "recursive": true,
      "file_patterns": ["*.log"]
    },
    {
      "source_id": "camera_sdk",
      "path": "business-logs/sdk",
      "recursive": true,
      "file_patterns": ["*.log"]
    }
  ]
}
```

| 参数 | 含义 |
| --- | --- |
| `source_id` | 来源唯一标识，云端命令的来源名称须与此一致 |
| `path` | 日志目录，相对路径以本 JSON 文件所在目录为基准 |
| `recursive` | `true` 扫描子目录，`false` 仅扫描当前目录 |
| `file_patterns` | 文件名匹配规则，例如 `*.log` |

项目支持该 JSON 文件中的 `//` 和 `/* ... */` 注释，通用严格 JSON 工具可能不支持。来源目录必须位于项目的 `business-logs/` 根目录内。

“文件模式”就是 Agent 直接从这个文件加载来源。业务程序只需向配置目录写日志，无需注册 MQTT 主题。

### 4.1 文件选择规则

按天拉取根据文件名中的有效 `YYYY-MM-DD` 日期，例如：

```text
business-logs/app/2026-10-19.log
business-logs/app/app-2026-10-19.1.log
business-logs/sdk/sdk-2026-10-19.log
```

- 文件名日期按北京时间解释；单次请求的时间范围最多 31 天。
- 选中后打包整份原文件，不解析日志行、时间戳或级别，不按内容裁剪。
- 文件内容出现当天日期，但文件名没有日期，按天模式不会选中。
- 文件修改时间是今天、文件名是昨天，按天模式仍按昨天处理。
- 最新文件模式不要求文件名日期，每个来源选修改时间最新的非空普通文件。
- 空文件、符号链接及不匹配规则的文件不采集。

Agent 不删除或改写业务原文件。采集以扫描到的文件长度为界，之后追加的内容可在下次采集中获取。修改来源配置需重启；在已配置目录新增文件，下次采集即可发现。

失败的命令不会因文件新增而自动重跑；重复命令 ID 会返回已保存结果，因此重试需创建新命令。

## 5. 查看运行日志、下载包和解压

### 运行日志

终端输出同时追加到项目下的 `run/agent.log`：

```bash
tail -n 100 run/agent.log
# 持续查看，Ctrl+C 退出查看。
tail -f run/agent.log
```

这是 Agent 连接、命令、错误记录，不是业务日志包。多次启动追加到同一文件，注意最后一次 `START` 之后的内容。在另一个终端中退出 `tail` 不会停止 Agent。

### 解压日志包

先在云端找到已完成的采集命令，打开对应文件的下载入口，将 `.tar.gz` 下载到电脑或 Ubuntu 设备。

如果使用 WSL，Windows 下载目录可通过 `/mnt/c/Users/Administrator/Downloads/` 访问。以下命令中的包名需替换为实际下载文件名；Ubuntu 原生环境请将目录替换为实际下载目录：

```bash
cd /mnt/c/Users/Administrator/Downloads
# 只看包内文件。
tar -tzf 实际文件名.tar.gz
# 解压到独立目录。
mkdir -p device-agent-extracted
tar -xzvf 实际文件名.tar.gz -C device-agent-extracted
```

包内包含业务原文件和 `manifest.json`，清单记录设备、命令、文件路径、大小及 SHA256 等信息。受包大小上限影响时，可能只保留部分整份文件，清单 `truncated` 会标记这种情况。

解压后可直接阅读业务日志原文件；`manifest.json` 用于核对采集内容。

### 目录区别

| 路径 | 内容 |
| --- | --- |
| `business-logs/` | 业务原始日志，Agent 不删除 |
| `run/agent.log` | Agent 运行日志 |
| `run/cloud-work/` | 真实云端临时目录，任务后清理 |
| `run/cloud-agent/commands/` | 真实云端命令结果缓存，PB 文件 |
| `run/cloud-agent/tokens/` | 真实设备 Token 缓存，请保留 |

最多保留 100 条命令结果，按更新时间清理旧记录，正在执行的任务不会被删除。这不会删除业务原日志或云端已上传的包。

## 6. 常见问题

| 现象或错误 | 检查方法 |
| --- | --- |
| PowerShell 执行后直接返回，没有启动输出 | 先进入 WSL，或使用第 3.3 节完整的 PowerShell 命令 |
| 找不到配置文件 | 先进入项目目录，程序从当前工作目录读取 `device-agent.conf` |
| `Connection refused` | 检查云端地址、端口、网络及 MQTT 服务是否可用 |
| 只有 `AUTH loaded...`，没有 `READY` | 只读到了缓存，继续检查连接、鉴权和握手输出 |
| MQTT 鉴权被拒绝或反复掉线 | 检查设备码与 Token 对应，避免多个 Agent 使用同一身份 |
| `invalid_enrollment_key` / `not_allowed` | 检查注册码及其允许的设备、机型范围 |
| `already_enrolled` | 恢复原 Token 或联系云端管理员，不要反复删除缓存注册 |
| Token 缓存无效或无法读取 | 检查文件及权限，恢复有效 Token，不要删除整个 `run/` |
| `UNKNOWN_SOURCE` | 云端来源名称须与 `source_id` 一致 |
| `INVALID_PATH` | 来源目录须位于允许的根目录内 |
| `NO_LOGS_IN_RANGE` | 检查文件名日期、请求日期、目录、文件名规则以及文件是否非空 |
| `BUSY` | 等当前任务结束后创建新命令 |
| `EXPIRED` | 创建有效期内的新命令 |
| `UPLOAD_DENIED` | 检查是否收到有效上传凭证及对应错误说明 |
| `UPLOAD_FAILED` | 检查对象存储地址、网络及 HTTP 结果；MQTT 连通不代表上传成功 |
| 新增日志后还是旧失败结果 | 用新命令 ID 重试，重复命令会返回缓存结果 |
| 握手成功但无命令 | 通过控制台或管理 API 创建采集命令，并核对设备码 |

不要仅根据临时目录为空判断失败，任务结束后会清理临时目录。优先查看命令结果与最终接收端。

## 7. 停止与检查进程

在启动 Agent 的终端按 Ctrl+C，等待退出；正在上传时可能需要等待当前操作结束。在其他 WSL 终端查看进程：

```bash
pgrep -af device-agent
```

确需从其他终端停止时，先核对 PID，再把下方 `12345` 替换为实际 PID：

```bash
kill -TERM 12345
```

停止设备端 Agent 后，云端服务继续运行；再次采集前需要重新启动 Agent 并完成握手。
